# Local backend verification

This is an evidence map, not a claim that every acceptance-plan bullet has a browser test. The acceptance specifications remain under `docs/plans/backend-acceptance/`.

## Recorded HTTP run

On 2026-08-31, the HTTP BDD suite completed with **14 passing scenarios, zero retries**: 13 desktop Chromium scenarios and one Pixel 7 mobile scenario. The final-code rerun also passed 14/14 in 2.1 minutes, after the request-ID audit, portable-alias validation and failed-check regressions. It used the actual local Worker, D1 and R2, all three migrations, and the complete canonical bilingual seed. The frontend adapter was explicitly HTTP. No browser mock supplied successful responses, and no native WebMCP registration was fabricated.

Run it with:

```sh
pnpm --filter @lorestra/e2e test:e2e:http
```

The harness owns port 4176 for Vite and 8795 for its Worker. Every scenario receives a private offline clone of a closed, seeded local store. Four synthetic opaque sessions are created through trusted local bindings, not through a public role-selection or reset endpoint. Trace, video and screenshot capture are disabled for this suite. The in-process Vite teardown avoids Windows shell-process-tree hangs; occupied ports fail instead of reusing or killing another server.

## Tooling and remaining acceptance work

```sh
pnpm test:tooling
```

The recorded tooling run completed with **7/7 passing tests** in 24.2 seconds on 2026-08-31. It covers canonical Markdown parsing, safe paths and symlink rejection, migrations and immutable triggers, storage restart, repeated imports without overwriting a live revision, invalid-import rejection, and backup/restore integrity.

| B24, B25       | Real D1/R2 restart; reviewed revision plus open proposal restored into separate empty bindings; business rows, path aliases and referenced object bytes match; sessions are absent; corruption and occupied restore targets are rejected     | No remote backup service or independent remote machine is involved                                                        |
| B39            | Portable export is read back and imported into a third empty D1/R2 store; both locale identities, exact UTF-8/emoji/CRLF bodies, versions, authors and relations survive; the old slug resolves and path aliases retain the same document ID | Portable export contains current surviving documents, not tombstones, historical revisions, proposal workflow or sessions |

The backup and portable roundtrip use a small bilingual subset of the same canonical vault for runtime cost; the separate seed test validates the complete vault. Portable export/import is not counted as full-history restoration. These checks are in `scripts/backend-seed.test.mjs`, `scripts/backend-runtime.test.mjs` and `scripts/backend-backup.test.mjs`.
