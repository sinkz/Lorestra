# What is Lorestra?

Lorestra is a portable knowledge vault with a calm reading surface, a reviewable proposal workflow, and an interface that people and agents can use together. Markdown remains the source of truth. The application makes it easier to discover context, connect related documents, and explain how a published revision came to exist.

Lorestra is designed around a simple promise: the next person should be able to act with less rediscovery and more confidence. A lesson from an incident, a product decision, an operating procedure, and an agent handoff can live in the same vault while keeping their audience and ownership explicit.

## Read first, publish deliberately

The public experience is read-only. A future authenticated workflow will let a person or agent propose a change, ask for review, and merge only after an explicit decision. A proposal is not a published document. Approval is not publication. The merge is the event that creates a new immutable version.

This separation gives the vault two useful properties:

1. Readers can trust that the visible body passed through an intentional review step.
2. Contributors can explore an idea without changing what everyone else sees.

## What Lorestra is not

Lorestra is not a second database that hides the source files. It is not a chat transcript, a list of unowned notes, or an agent that silently edits official knowledge. The vault should remain exportable and understandable without the web application.

Start with the [Using Lorestra](using-lorestra.md) guide, then inspect [Security and governance](security-and-governance.md) before adding sensitive material.
